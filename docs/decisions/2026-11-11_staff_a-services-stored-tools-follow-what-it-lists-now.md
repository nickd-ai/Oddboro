- [staff] **Decision (2026-11-11): a service's stored tools follow what it lists now: the office reads them on each run that uses it, when the owner opens its actions on the Settings tab, and on the owner's Refresh, never on a timer, and keeps the tool list, what Read only reaches (the same rule as connecting, both ways), and what each tool does.** Servers add, drop and remark tools, and a list stored once went stale: the Services page showed tools that were gone, Read only never gained a new read tool without reconnecting, and a dropped tool kept its standing yes, so a new tool by that name would have gone through without asking. Now a dropped tool leaves every standing yes, and so does one whose description changed, since the owner said yes to what it did; a dropped Ask first tool passes Ask first to the tools added with it, since a rename is a drop and an add, and each change but a description gets a Ledger line. Physical mail keeps the three reads the office picked at setup. A service no run uses changes nothing the office does, so it is read when the owner looks at it (2026-11-12, superseding a read at start and once a day, which hard rule 13 rules out). Like Claude Code, which lists a server's tools at each session's start, the live list wins; the office keeps a copy because its page has no open connection to read.
