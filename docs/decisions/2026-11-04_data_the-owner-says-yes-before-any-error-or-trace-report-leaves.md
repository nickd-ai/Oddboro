- [data] **Decision (2026-11-04): the office sends error and tracing reports only after the owner says yes, and the owner can say no again at any time; a packaged build sends them through New Altitude's shared relay, which alone holds the Sentry key, and only while the owner is signed in to a New Altitude account, each report carrying the sign-in's access token, which New Altitude checks and never passes to Sentry, and a build from source sends nothing unless its owner names their own Sentry.** Nothing leaves the office without the owner's yes, and reports are no exception. The owner turns reports on with the Diagnostics switch in Setup, which shows only when reports can go (for New Altitude's relay, while signed in), and neither the first visit nor the Desk asks, so a new owner gets to work sooner (the owner ruled so on 2026-11-08); with no answer nothing is sent. The answer is `OFFICE_DIAGNOSTICS` in the office's `.env`, which the shell reads too. Reports carry no IP address, computer name, cookies, headers, request bodies, query strings, chats, Odds' work or anything from the owner's files, no address the office reaches (every request it makes is named by its method alone), no folder under the home folder but Oddboro's own (any other file there is named by its file name alone), no folder of a file the shell loads (named by its file name alone), and of the device only the chip; Sentry keeps only the approximate location (city and country) the address points to. An error's message is included only in a shape code writes: an engine error's template, a system error's code and call, a Postgres error's code with the names of the table, column and constraint it touched, or a message Oddboro's code wrote. The office page sends through the office, never to the relay. Decided by Ryan Holmes for New Altitude. Code in `apps/office/src/lib/server/diagnostics.ts` and `apps/desktop/src-tauri/src/diagnostics.rs`; what is sent is in the privacy policy. Supersedes the 2026-11-04 wording that sent reports without a sign-in.
